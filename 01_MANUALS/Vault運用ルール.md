# Vault運用ルール

人間も AI も、このルールに沿ってノートを書きます。全部を最初から守る必要はありません。AI に頼めば揃えてくれます。

## 1. 命名規約

| 対象 | ファイル名 | 例 |
|---|---|---|
| 人（家族以外・`50_PEOPLE/`） | `所属_氏名.md` | `サンプル株式会社_山田太郎.md` |
| 家族（`20_PERSONAL/家族/`） | `家族_名前.md` | `家族_花子.md` |
| 組織 | 正式名称 | `サンプル株式会社.md` |
| テーマ | 短い名詞 | `生成AI活用.md` |
| デイリーノート | `YYYY-MM-DD.md` | `2026-10-27.md` |
| プロジェクト | `YYYY_名前/` フォルダ | `30_WORK/projects/2026_新商品企画/` |
| AI の生成物 | `YYYYMMDD_内容.md` | `00_AI/reports/20261027_週次振り返り.md` |
| フォルダの説明ノート | `フォルダ名.md` | `50_PEOPLE/50_PEOPLE.md` |

- ファイル名に `/ \ : * ? " < > |` を使わない
- 所属が分からない人は `所属不明_氏名.md`、フリーランス等は `個人_氏名.md`
- 同じ人・組織のノートを2つ作らない（作る前に検索）

## 2. frontmatter 規約

ノートの先頭に、次のようなプロパティを書きます。

```yaml
---
created: 2026-10-27T16:40:00+09:00
updated: 2026-10-27T16:40:00+09:00
type: person
tags:
  - person
---
```

| キー | ルール |
|---|---|
| `created` | 作成日時。**一度書いたら書き換えない** |
| `updated` | 最終更新日時。編集したらここだけ更新する |
| `type` | ノートの種類: `person` / `organization` / `topic` / `project` / `daily` / `manual` / `index` / `report` / `prompt` / `clip` など |
| `tags` | 自由。リスト形式で書く |
| `source` | （任意）外部資料の出典 URL など |

- 日時は **ISO 8601 + タイムゾーン**（`2026-10-27T16:40:00+09:00`）。デイリーノートの `date` だけは日付（`2026-10-27`）
- 同じキーを2回書かない。インデントにタブ文字を使わない（YAML エラーになります）
- 値に `:` を含むときは `"..."` で囲む

## 3. リンク規約

- 人・組織・テーマに触れたら `[[wikilink]]` にする（例: `[[サンプル株式会社_山田太郎]]`）
- 表示名を変えたいときは `[[サンプル株式会社_山田太郎|山田さん]]`
- リンク先がまだ無くてもOK（あとでノートを作れば自動でつながる）。ただし表記は既存ノートに合わせる
- 人のノートには所属組織へのリンクを、組織のノートには関係者・関連テーマへのリンクを書く。つながりがグラフビューで見えるようになります

## 4. 移動と削除

- 削除しない。不要になったら `90_ARCHIVE/` へ移動する
- 例外: サンプルノートは削除してOK（このパッケージ同梱の例のため）
- Obsidian の中で移動すると、リンクは自動で更新されます
